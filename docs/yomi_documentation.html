Overview

1.1 What is Yomi?

Yomi (読み — Japanese for "reading") is a feature-complete manga and manhwa reader for Android. It provides a polished, distraction-free reading experience built entirely with Flutter's Cupertino widget set, giving it the feel of a native iOS application while running on Android hardware.

The application manages a personal library of saved titles, downloads chapters for offline reading, connects to pluggable content sources, and backs up your entire reading history to a local JSON file or Google Drive.

1.2 Core Design Principles

🎨

Immersive, minimal UI

Dark-first design with a deep navy background. Frosted glass overlays, ambient radial glows, and tap-to-reveal chrome keep reading the focus.

⚡

Reactive, no loading flickers

Isar's reactive streams drive every list. Shimmer placeholders replace blank screens during cold loads. State updates propagate instantly via Riverpod.

🔌

Pluggable sources

Content sources are plain Dart classes implementing a MangaSource interface. Zero build-time coupling — register and use.

🌗

Adaptive light & dark

The AppColorsX context extension resolves every colour at runtime. Switching themes is instant — no restart required.

Features

2.1 Library

The Library tab is the home screen. It shows every manga you have saved in a two-column grid.

  • Real-time search — a frosted search bar at the top filters titles as you type. Closes with a Cancel button.
  • Filter sheet — a bottom sheet lets you narrow by read status (All / Unread / Read / Downloaded) and filter on genres.
  • Categories — user-defined shelves (created in Settings). Each manga can belong to multiple categories. A horizontal chip row above the grid switches between them.
  • Unread badge — displayed on the card corner when there are unread chapters.
  • Shimmer skeleton — animated placeholder grid shown while the database loads.
  • Ambient radial glow — subtle blue glow in the top-left of the library background.

2.3 Downloads

Chapters can be downloaded for offline reading. The Downloads tab shows the active queue and completed history.

  • Queue — chapters process one at a time. While downloading, a progress bar shows the current page count.
  • Pause & Resume — any queued or downloading chapter can be paused. Resuming picks up from the page it left off.
  • Cancel — removes the entry from the queue. Partially downloaded files are discarded.
  • Retry — failed chapters show a retry button.

2.4 Browse & Sources

The Browse tab lists all registered content sources. Tapping a source opens its manga catalogue.

  • Popular and Latest Updated listings with infinite scroll.
  • Search within any source.
  • Sort control (Popular / Latest) in the source listing.
  • Tapping a manga opens the title detail sheet, where you can add it to your library.

2.5 Backup & Restore

Yomi can export your entire library to a human-readable JSON file and restore from any previously saved backup.

  • Export — creates {appDocuments}/backups/yomi_backup_YYYYMMDD_HHmmss.json with all manga metadata, chapters, read status, categories, and download status.
  • Restore — imports a backup file and merges it into the current library. Existing entries are updated; new entries are inserted. Read and download status is preserved.
  • The Restore Backup screen lists all available backups with a one-tap restore flow and a confirmation dialog.
ℹ️
Backup files are plain JSON and can be viewed or edited with any text editor. The schema is forwards-compatible — fields not recognised by an older version of Yomi are silently ignored on restore.

3.3 State Management

All state is managed by Riverpod v2. The app uses several provider types:

Provider typeUsed for
StateProviderSimple values: brightness, reading direction, page scale, background, search query
StreamProvider.familyIsar reactive streams — library list, chapter status, live manga object
FutureProvider.familyAsync loads — manga detail, chapter list, page URLs
NotifierProviderComplex mutation logic — library CRUD, category management
AsyncNotifierProviderDownload manager — queue, pause/resume/cancel, progress tracking
ℹ️
ReaderState overrides == and hashCode so that Riverpod's equality check prevents redundant rebuilds when only unrelated fields change (e.g., a chrome toggle does not invalidate the page-counter widget).

3.5 Theming

Yomi uses a custom dark-first palette defined in AppColors with a parallel light set, resolved at runtime through the AppColorsX extension on BuildContext: 

// Use in any StatelessWidget or ConsumerWidget build method:
final bg      = context.backgroundColor;       // dark: #0A0A0F  light: #F2F2F7
final surface  = context.surfaceColor;          // dark: #141418  light: #FFFFFF
final elevated = context.surfaceElevatedColor;  // dark: #1C1C24  light: #ECECF0
final border   = context.borderColor;           // dark: 8% white light: 8% black
final textSec  = context.textSecondaryColor;    // 60% on/off

Primary text styles (nav title, body, section title) inherit colour from CupertinoTheme's DefaultTextStyle so they adapt automatically. Secondary and tertiary text uses explicit context.*Color calls.

Source Plugin System

4.1 MangaSource Interface

Every content source must implement the MangaSource abstract class located at lib/core/extensions/source_interface.dart. 

abstract class MangaSource {
  // ── Identity ───────────────────────────────────────────────
  String get id;          // unique slug, e.g. 'asurascans_en'
  String get name;        // display name
  String get baseUrl;     // root URL for web links
  String get language;    // ISO 639-1 code
  String get version;     // semver string
  Uint8List get iconBytes; // source icon PNG bytes

  // ── Image headers (sent with every page request) ──────────
  Map<String, String> get imageHeaders;

  // ── Filters (optional) ────────────────────────────────────
  List<SourceFilter> getFilters();

  // ── Listings ──────────────────────────────────────────────
  Future<List<MangaSummary>> fetchPopular({int page = 1});
  Future<List<MangaSummary>> fetchLatestUpdates({int page = 1});
  Future<List<MangaSummary>> search(
    String query, {int page = 1, List<SourceFilter> filters});

  // ── Detail ────────────────────────────────────────────────
  Future<MangaDetail> fetchMangaDetail(String mangaId);
  Future<List<ChapterInfo>> fetchChapterList(String mangaId);

  // ── Pages ─────────────────────────────────────────────────
  Future<List<String>> fetchPageUrls(String chapterId);
}

4.2 Built-in Sources

AsuraScans (asurascans_en)

  • API base: https://api.asurascans.com/api
  • Chapter ID format: seriesSlug::chapterUUID::chapterNumber
  • fetchPageUrls uses a 3-strategy fallback:
    1. GET /series/{slug}/chapters/{uuid}
    2. GET /series/{slug}/chapters?number={num}
    3. GET /chapters/{uuid}
  • Sends Origin: https://asuracomic.net and Referer headers with every request.

AllManga (all_manga_en)

  • API base: https://api.allanime.day/api (GraphQL)
  • Chapter ID format: mangaId::chapterNumber
  • _query tries POST (standard GraphQL) first, falls back to GET on DioException.
  • Image URLs that are relative paths are prefixed with https://ytimgf.fast4speed.rsvp.

4.3 Adding a New Source

  1. Create a new file in lib/core/extensions/sources/my_source.dart.
  2. Implement the MangaSource interface.
  3. Open lib/core/providers/source_registry_provider.dart and add your source instance to the registry list.
⚠️
Image headers must include Referer and Origin for any source that hot-links images — many CDNs reject requests without these headers.

5.2 Build & Run

1. Clone and fetch dependencies

git clone https://github.com/tsnyders/comic-center.git
cd comic-center
flutter pub get

2. Generate code

Isar schemas and Riverpod annotations require code generation:

dart run build_runner build --delete-conflicting-outputs
⚠️
Never manually edit *.g.dart or *.freezed.dart files — they are regenerated on every build_runner run and your changes will be lost.

3. Run

# Debug on a connected device or emulator
flutter run

# Release build (optimised APK)
flutter build apk --release

4. Analyse

flutter analyze
# Expected: all issues at info level only (deprecation warnings)

Android package ID

⚠️
The applicationId is com.comiccenter.comic_center. Do not change this. Android ties installed apps to their package ID; changing it would require users to uninstall and reinstall, losing all local data.

Update Check

Check for Updates calls the GitHub REST API: https://api.github.com/repos/tsnyders/comic-center/releases/latest

  • HTTP 200 — a release exists. Displays version tag and changelog body. If an APK asset is attached, a Download button opens the URL via the native Android intent.
  • HTTP 404 — no releases published yet. Displays "No Updates Available".
  • Network error / timeout — throws UpdateCheckException. Displays "Error" with the specific message.

Backup & Data

Backup File Format

Backups are stored as UTF-8 JSON at:

{appDocumentsDirectory}/backups/yomi_backup_YYYYMMDD_HHmmss.json

Top-level structure:

{
  "version": 1,
  "exportedAt": "2026-06-07T10:30:00Z",
  "categories": ["Favourites", "Reading"],
  "manga": [
    {
      "id": 42,
      "title": "Solo Leveling",
      "sourceId": "asurascans_en",
      "sourceMangaId": "solo-leveling-abc123",
      "coverUrl": "https://…",
      "categories": ["Favourites"],
      "chapters": [
        { "sourceChapterId": "…", "number": 1, "isRead": true, "isDownloaded": false }
      ]
    }
  ]
}

Restore Behaviour

The restore operation performs an upsert merge:

  1. For each manga in the backup, find the existing record in Isar by sourceId + sourceMangaId.
  2. If found, update metadata fields but preserve isRead and isDownloaded on chapters.
  3. If not found, insert as a new entry.
  4. Categories in the backup are merged with existing categories (no duplicates).
ℹ️
A restore never deletes existing data — it only adds or updates. To start fresh, you must clear app data from Android Settings before restoring.

Pull-to-Refresh (Chapter Refresh)

Pulling down on the chapter list in a manga's detail sheet triggers refreshMangaChapters, which re-fetches the chapter list from the source and upserts changes into Isar:

  • New chapters are inserted.
  • Existing chapters have their title, number, and uploadDate updated.
  • isRead and isDownloaded are never touched.
  • chapterCount and unreadCount on the parent MangaEntry are recalculated.
